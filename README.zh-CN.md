我不需要AI说得更自信。我需要它真正理解我的情况，研究现在正在发生什么，说明证据在哪里停止，并告诉我第一步先做什么。

所以，我把这套工作方法做成了一个Codex Skill。

现在它开源了——但仍然诚实地处于Beta阶段。

---

> **重要：**这是一套决策过滤器，不是答案机器。它负责检索、比较和排序；当来源受阻、过期、互相矛盾或样本不足时，它应该明确说“证据还不够”。最终决定和行动仍然由你掌握。

## 这是什么？

**循证个人决策顾问**把Codex变成一位研究驱动的职业、教育与个人成长决策伙伴。

给它一个目标、你的限制，以及你真正拥有的证据，它可以：

- 检索最新的官方、学术、公司和市场来源；
- 区分有来源支持的事实、推断、预测和建议；
- 把市场要求与你真实拥有的项目、技能和限制进行对照；
- 只使用确实可能改变决定的分析模型；
- 展示矛盾、无法访问的来源和低可信度结论；
- 先给一个方向和不超过三项立即行动，再按需展开细节；
- 设置复盘日期，让建议随着现实变化而更新。

目前最成熟的是职业模块：近期JD抽样与去重、细分岗位比较、简历证据差距、技能优先级，以及符合个人时间预算的30/60/90天计划。

## 最终会得到什么？

```text
结论
先验证AI运营，不要把AI产品经理设为唯一方向。
你目前的数据分析证据强于产品所有权证据。

接下来三件事
1. 把一个项目改写成“用户问题→决定→结果”案例。2小时。
2. 标注10条可用公司官网JD中的重复要求。90分钟。
3. 请两位从业者只评审这个案例。45分钟。

证据
事实｜中可信度：[有日期和引用的当前市场信号]
你的证据：[只使用附件真正支持的内容]
推断：[为什么更接近某个细分岗位]

最大限制
两个指定招聘平台无法访问，因此样本只能用于方向判断。

复盘
完成10次定向投递或2次从业者访谈后更新判断。
```

目标不是生成更长的报告，而是得到一项可以检查的决定：**知道什么、不知道什么、与你有什么关系、下一步做什么。**

[虚构的精简示例](examples/early-career-ai-role-brief.md)只展示输出形态，不代表最新市场证据或效果证明。

## 它能做什么？

| 能力 | Skill会做什么 | Skill不会假装什么 |
|---|---|---|
| 最新研究 | 在时效重要时优先使用近期一手与权威来源 | 所有平台和页面都可以访问 |
| 证据校准 | 给核心结论标注高、中、低可信度 | 一个著名模型就能证明事实 |
| 个性化 | 根据你提供的限制和可检查证据给建议 | 你拥有没有提供的技能或经历 |
| 职业分析 | 去重JD，区分必需、加分和背景信号 | 招聘广告数量等于全部市场需求 |
| 行动计划 | 先给不超过三项行动、所需投入和完成标准 | 用户拥有无限时间和精力 |
| 结果复盘 | 在复盘节点比较行为与结果信号 | 一次好评或前后对比就证明因果关系 |
| 效果评测 | 对比基础提示词与Skill，并报告成本和失败 | 结构测试通过就等于真实有效 |

## 快速开始

需要安装**Codex**和**Python 3.9+**。

下载或克隆本仓库，在仓库目录打开终端并运行：

```bash
python3 scripts/install.py
```

安装器会先验证仓库，再把Skill复制到`${CODEX_HOME:-~/.codex}/skills/evidence-based-personal-advisor`。如果目标已经存在，它会停止，不会直接覆盖。

在下一个Codex回合中输入：

```text
使用 $evidence-based-personal-advisor：

我是数据科学应届生，目标是深圳AI产品或AI运营岗位。
请研究最近六个月的行业和岗位趋势，抽样分析近期JD，结合我的简历
找出证据差距，并给出30/60/90天行动计划。请区分事实、推断和建议，
标注证据可信度与检索限制。我每周可以投入6小时。
```

安装后也可以自然提问：

```text
请结合最新证据和我的个人限制，帮我比较这几个职业方向。
```

## 给它真正有用的背景

问题越具体，结果越有用。只提供完成决策所需的内容：

- 目标岗位和地区；
- 做决定的时间；
- 每周时间、预算和不能妥协的限制；
- 删除不必要身份信息后的简历、作品集、成绩单或项目证据；
- 你如何定义成功，以及想避免什么。

如果用户要求简历差距分析，却没有提供简历或事实背景，Skill必须先索取材料，不能凭空构造候选人画像。

## 三种研究档位

| 档位 | 适用情况 | 典型范围 |
|---|---|---|
| `quick` | 快速了解、“先给方向”、低成本试探 | 4–8个有效来源、1–2个模型、精简回答 |
| `standard` | 大多数职业和教育决策 | 8–15个有效来源、2–4类来源、1–3个模型 |
| `deep` | 明确要求系统比较或影响重大的决定 | 更广纳入规则、矛盾图谱、明确检索限制 |

这些范围用于控制成本，不是凑数量。连续两轮搜索都没有新增会改变决定的信息时，研究应该停止。

## 职业分析流程

```text
最新来源与去重后的JD
          │
          ▼
标准化岗位要求
          │
          ▼
你的可检查证据（A/B/C/D/U）
          │
          ▼
匹配、证据差距、技能差距或经验差距
          │
          ▼
立即做 · 低成本验证 · 下一步构建 · 暂缓
```

候选人证据与来源可信度始终分开。高质量市场来源可能恰好说明候选人的证据不足；一个记录清楚的项目也不会因为市场需求暂时不确定而变成低质量个人证据。

完整运行与评测流程见[架构说明](ARCHITECTURE.md)。

## 隐私与控制权

这是安装在本地的Skill，不是托管简历服务。本仓库不会接收或收集你的数据。

但“本地安装”不等于“离线推理”：你交给Codex的材料可能会由当前环境使用的AI提供商和工具处理，请检查相应条款与设置。Skill会要求Codex不要把简历原文、身份信息、联系方式和机密记录放入网页搜索或外部查询。

它不会自动投递、联系雇主、公开文件或收集评测数据。分享什么、执行什么，决定权始终在你。

## 不要相信它，评测它

评测协议会在基础提示和Skill条件之间保持提示、材料、模型、工具、研究时间窗和时间预算一致，并检查：

- 引用是否真正支持结论；
- 事实、推断、预测和建议是否混淆；
- 是否只使用用户真实提供的证据；
- 行动是否具体、可完成、可验证；
- 新用户能否看懂第一项行动；
- Token、耗时、实际成本、缺失数据和严重失败。

python3 skills/evidence-based-personal-advisor/scripts/summarize_evals.py --template

汇总成对JSONL记录：

原始提示、简历、姓名、雇主身份和模型完整输出不能放进公开仓库。提交结果前请阅读[效果评测与用户反馈协议](skills/evidence-based-personal-advisor/references/evaluation-and-user-feedback.md)。

## 常见问题

**这是自动求职系统吗？**

不是。它负责研究和建议，不会自动投递、联系招聘者或跟踪申请。

**它会爬取BOSS直聘、LinkedIn或Indeed吗？**

Skill本身没有内置爬虫。Codex使用当前环境提供的网络能力，并必须说明受阻、个性化或无法访问的来源。

**它会帮我修改简历吗？**

它可以诊断证据差距并重写已有事实，但不能创造虚假成绩、个人贡献或量化结果。

**为什么不继续加入更多商业或学术模型？**

因为模型很多，验证很少。[路线图](ROADMAP.md)优先处理成对测试、失败案例和真实用户反馈。

**可以用于职业以外的问题吗？**

可以，但目前职业研究模块最完整，其他场景的效果还没有被证明。
